If your CPMS or charger integration does not push sessions automatically, submit them directly via the Rightcharge API. This guide covers the submission format, idempotency, validation errors and bulk submission.

## Submit a single session

<Steps>
  <Step title="Build the session payload">
    Include the following fields in your request body. All timestamps must be in ISO 8601 format with timezone.

    | Field | Type | Required | Description |
    | --- | --- | --- | --- |
    | `driver_id` | string | Yes | Rightcharge driver identifier |
    | `charger_id` | string | Yes | Rightcharge charger identifier |
    | `start_time` | string | Yes | Session start timestamp (ISO 8601) |
    | `end_time` | string | Yes | Session end timestamp (ISO 8601) |
    | `energy_kwh` | number | Yes | Energy delivered in kilowatt-hours |
    | `external_session_id` | string | Yes | Stable identifier from your system |
    | [PLACEHOLDER: additional fields] | [PLACEHOLDER: confirm additional optional fields] | No | [PLACEHOLDER: describe any optional fields] |
  </Step>
  <Step title="POST the session">
    <CodeGroup>

    ```bash
    curl -X POST [PLACEHOLDER: https://api.rightcharge.co.uk/v1/sessions] \
      -H "Authorization: Bearer YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "driver_id": "drv_def456",
        "charger_id": "chr_ghi789",
        "start_time": "2024-01-15T18:00:00Z",
        "end_time": "2024-01-15T22:30:00Z",
        "energy_kwh": 24.5,
        "external_session_id": "session-2024-01-15-001"
      }'
    ```

    </CodeGroup>
  </Step>
  <Step title="Handle the response">
    Expected success response:

    ```json
    {
      "id": "sess_jkl012",
      "driver_id": "drv_def456",
      "charger_id": "chr_ghi789",
      "start_time": "2024-01-15T18:00:00Z",
      "end_time": "2024-01-15T22:30:00Z",
      "energy_kwh": 24.5,
      "external_session_id": "session-2024-01-15-001",
      "status": "received",
      "created_at": "2024-01-15T22:31:00Z"
    }
    ```

    Rightcharge processes the session asynchronously. You will receive a webhook when processing completes. See [api-reference/webhooks/events](/api-reference/webhooks/events) for event details.
  </Step>
</Steps>

## Idempotency

Rightcharge uses `external_session_id` as an idempotency key. If you submit a session with an `external_session_id` that already exists, Rightcharge returns the original session record without creating a duplicate.

This is useful when:

- Your system retries a submission after a network timeout
- A CPMS pushes the same session multiple times
- You are backfilling historical data and want to avoid duplicates

<Warning>
  Choose a stable, deterministic `external_session_id`. Do not generate a new random ID on retry. Use the same identifier your CPMS or charger source uses.
</Warning>
