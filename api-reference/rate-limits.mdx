## Handling 429 Too Many Requests

When you exceed a rate limit, the API returns `429 Too Many Requests`. Implement exponential backoff with jitter to retry safely.

The `Retry-After` header indicates when you may retry [PLACEHOLDER: confirm `Retry-After` header name and format — engineering to confirm].

### Bash example

```bash
# Retry with exponential backoff
for i in 1 2 4 8; do
  response=$(curl -s -o /dev/null -w "%{http_code}" -X GET "https://[PLACEHOLDER: base URL]/v1/drivers" \
    -H "Authorization: Bearer YOUR_API_KEY")
  if [ "$response" != "429" ]; then
    break
  fi
  sleep $i
done
```

### Pseudocode

```python
import time, random

def request_with_backoff(url, headers, max_retries=5):
    for attempt in range(max_retries):
        response = http_get(url, headers=headers)
        if response.status != 429:
            return response
        delay = (2 ** attempt) + random.uniform(0, 1)
        time.sleep(delay)
    raise Exception("Rate limit exceeded after maximum retries")
```
